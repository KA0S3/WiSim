# Running larger systems and recovering calculations

There is no automatic wall-clock cutoff. A calculation taking more than 12 seconds continues; elapsed time produces a non-blocking progress notice, not a stopped simulation. Engine loading, circuit preparation, solving and reading preparation have separate status messages. Before the first result, readings show a dash rather than inventing a zero measurement.

The editor stays available during a calculation. **Cancel calculation** explicitly stops the current worker. Editing the circuit cancels obsolete work and calculates the latest revision. **Retry calculation** keeps the last valid simulation time, battery charge, capacitor/inductor state and protection state. Only the existing **Reset simulation** action deliberately starts those conditions again.

An actual worker crash or failed numerical result triggers bounded recovery from the last committed state, with shorter simulation windows where appropriate. Ordinary 50/60 Hz measurements still include a complete source cycle. If numerical recovery fails, the calculator pauses its readings and explains the error; project data remains saved and editable. This is separate from an electrical fault in the sandbox, which is permitted and shown with callouts/diagnostics.

Large-network changes include selective ngspice signal export, transferable waveform buffers, fewer redundant samples for algebraic DC networks, indexed retained-node lookup and removal of state belonging to deleted equipment. AC sources and stored-energy models retain fine transient sampling.

A separate upstream bridge bug could leave a failed numerical calculation waiting forever: its raw-output exception never rejected the JavaScript promise. The pinned bridge is now patched reproducibly; actual output/startup failures reject, carry solver details and enter the existing recovery path. Old raw output is removed before each solve. Missing terminal/current exports, inconsistent series lengths or unordered times are rejected rather than becoming invented zero readings. See UPSTREAM.md for the patch and real-failure regression.

After updating an already-open preview, refresh the page once to load the current worker. No project reset or deletion is required. The development preview now excludes the solver bridge from Vite's persistent dependency optimisation cache. `npm run ui:dev` checks actual displayed readings, changed demand, saved-project reload and real browser-worker failure/recovery at http://127.0.0.1:5173 (or WISIM_URL).

The user's supplied eight-device project exposed a second concrete cause: a disconnected illuminated PV panel made the clipped behavioural exponential fail at open circuit, so the entire network had no result. The generic PV curve now uses a photocurrent source and native ngspice diode, which provides numerical voltage limiting. Open-circuit voltage and negligible branch current are calculated without removing the panel or changing the circuit. Regressions verify the same I/V assumption across loads/irradiance, energy balance and continuing AC/storage readings with the mismatched controller settings preserved. Run `node scripts/project-simulation-browser-check.mjs <project.json>` for an explicitly supplied project; WISIM_URL optionally selects the running development preview, otherwise the command owns a production preview. The input file is read only.

`npm run ui:recovery` verifies a reply deliberately delayed beyond 12 seconds, recovery after injected worker failures, state retention, editing a failed circuit and explicit cancellation/resume. It tests lifecycle behaviour; it does not pretend the delayed reply is an expensive physical solve.

`npm run ui:large` separately runs real connected 100/250/500-device DC networks and a coupled 500-device solar/storage/inverter/AC network using ngspice in the production browser worker. It verifies continuing live frames, transferred sample data, responsive Pause and DC source/load/cable power balance. The solar case has 100 panels, 50 string fuses, a controller, storage, an inverter, distribution and AC/DC loads. These are performance fixtures with generic models, not installation recommendations.

The current v4 project limit remains 500 equipment items and 2,000 conductors. Testing those four fixtures does not establish correctness/performance for every possible topology or larger projects. Actual numerical failures remain visible; they are not hidden to make the app appear to be running. See PERFORMANCE.md for measured timings and STATUS.md for remaining scope.
