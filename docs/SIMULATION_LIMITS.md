# Simulation boundaries

WireSim is a deterministic educational model driven by the shared terminal-aware project. It currently exposes PV output and cold Voc, simplified MPPT capping, battery current/SOC, conductor and modeled lug voltage drop with I²R loss, bounded parallel-conductor effects, AC apparent power/current, inverter overload, protection diagnostics, topology validation, active paths, open terminals, terminal readings, device state, and explicit AC profile compatibility.

Verified MPPT models use their sourced nominal PV input-power table for the selected 12 V, 24 V, or 48 V battery-system class where that table is available. Modeled charging is capped by the lower controller and battery charge-current limit. Generic controllers use a learner-set power cap. The model does not solve PV string voltage/current, controller conversion curves, thermal derating, BMS behavior, or manufacturer charging algorithms. See [CATALOG_SOURCES.md](CATALOG_SOURCES.md) for the exact verified record sources.

Supported teaching profiles are 120 V/60 Hz single-phase, 230 V/50 Hz single-phase, 120/240 V/60 Hz split-phase, and 400 V/50 Hz three-phase. The profile is part of the project model; it is not a decorative label. Split/three-phase templates expose A/B/C terminals and the engine refuses a profile until the required phase endpoints are wired. The current bounded engine does not yet solve arbitrary Kirchhoff networks, waveform-level AC, transfer switching, certification-grade protection, installation derating, physical telemetry, or every three-phase branch behavior. Unsupported or invalid terminal connections are reported rather than given fabricated readings.

Power-source reachability and bus-branch current estimates use only wires with resolved terminal IDs joining compatible DC or AC terminal roles. A learner may save a wire between incompatible domains or polarities to study the mistake: it remains visible, receives a focused warning and brief reduced-motion-aware pulse, but is excluded from active modeled paths and does not imply an energized connection. Data/control and earth links do not carry modeled power, and legacy endpoint-only wires remain saved but unresolved; they do not imply a guessed energized path. The topology graph still treats a device node as a coarse bridge between its modeled power terminals, so it is not a circuit-level or Kirchhoff solution.

A green result is not installation approval. Verify real systems against current manufacturer documentation and applicable standards.

The learning meter's resistance mode can calculate the nominal 20 °C DC resistance of one active directly connected wire from its saved material, length, area, and parallel count. Continuity checks for a path through active modeled wires between both selected leads; it does not traverse internal device paths. Current mode can report a bounded downstream load estimate for a directly measured DC bus branch, using connected load watts, the simplified conversion efficiency, and battery voltage. It does not solve Kirchhoff current distribution or branch conductor drop. Other DC connections report the system-level estimate, and AC connections report the system apparent-power estimate. Lead direction is not solved. These are educational estimates, not physical meter readings.

Inverters can carry nominal DC input and AC output voltage/frequency settings. The simulator compares DC input by 12/24/48 V battery class and AC output against the selected system profile. A mismatch marks those inverter terminals unsupported and raises a diagnostic; it does not model voltage conversion, DC input range/cutoff, output frequency dynamics, or a full inverter operating envelope.
